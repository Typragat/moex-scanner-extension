# MOEX Price Scanner: технический контекст

Дата актуализации: 2026-08-30.

## Статус

Рабочая папка — корень репозитория.

Базовый код восстановлен из стабильной локальной версии Projects.

После переключения выполнена локальная миграция T-Invest API: новый домен tbank.ru, актуальные поля instrumentId и отдельный статус сетевой или сертификатной ошибки. Поэтому рабочая папка больше не совпадает побайтово с версией Projects.

Экспериментальная майская версия была сохранена в отдельный локальный архив перед переключением. Архив не входит в репозиторий и не является релизом.

## Источники истины

- Пользовательские ожидаемые сценарии должны подтверждаться явным решением пользователя или утверждённой документацией.
- README описывает текущее наблюдаемое поведение и известные ограничения, но сам по себе не создаёт новые продуктовые требования.
- Реализация помогает понять фактическое состояние, но не должна автоматически превращаться в обязательное ожидаемое поведение.
- Экспериментальный handoff от 15 мая является историей инцидента, а не инструкцией к восстановлению кода.

## Назначение

Manifest V3 расширение добавляет fixed overlay в веб-терминал Т-Инвестиций и показывает тикеры с резким изменением цены.

Основной сценарий:

1. Получить список инструментов через T-Invest API.
2. Получить состав IMOEX через MOEX ISS при выбранном фильтре.
3. Каждые три секунды запросить последние цены пакетами.
4. Сохранить отдельную историю для каждого FIGI.
5. Для каждого тикера выбрать площадку с самой свежей сделкой.
6. Рассчитать изменение внутри истории выбранного FIGI.
7. Применить threshold и ticker-level cooldown.
8. Добавить сигнал в таблицу и при необходимости воспроизвести звук.

## Архитектура

### manifest.json

- Manifest V3.
- Подключает content.js и widget.css на www.tbank.ru/terminal и старом алиасе www.tinkoff.ru/terminal.
- Объявляет host permissions для T-Invest API, MOEX ISS и терминала.
- Не выполняет скрипты в MAIN world.
- Не подключает sanitizer или React/Redux bridge.

### background.js

- Инициализирует настройки.
- Маршрутизирует сообщения между popup и content scripts.
- Выполняет API_FETCH с host permissions расширения.
- Преобразует низкоуровневый Failed to fetch в NETWORK_OR_CERTIFICATE без вывода токена в логи.
- Хранит алерты и статус в chrome.storage.session.
- Зеркалирует только hiddenTickers, interestingTickers и interestingOnly в chrome.storage.sync.
- Не синхронизирует токен.

### content.js

- Живёт, пока открыта вкладка терминала.
- Монтирует overlay.
- Держит polling через setInterval.
- Загружает инструменты и регистрирует FIGI в scanner.js.
- Рендерит таблицу и применяет TTL.
- Реализует direct, search-flow и text fallback для активации тикера.

### lib/api.js

- Shares и Futures запрашиваются со статусом ALL.
- Оставляются рублёвые MOEX или FORTS/MOEX варианты.
- Разные площадки одного тикера не дедуплицируются на API-слое.
- GetLastPrices вызывается по массиву FIGI.
- BASE использует invest-public-api.tbank.ru/rest.
- GetCandles и GetLastPrices отправляют instrumentId. В качестве значения используется FIGI, что поддерживается текущим контрактом.
- Транспортные ошибки нормализуются в NETWORK_OR_CERTIFICATE.

### lib/scanner.js

- buffersByFigi хранит независимый ring на каждый FIGI.
- figiToInstr связывает FIGI с тикером и площадкой.
- На каждом тике активный FIGI выбирается по максимальному полю time.
- Цена старше часа игнорируется.
- Cooldown хранится по тикеру.
- Размер истории ограничен шестью минутами.

### popup

- Настройки сканирования.
- Список инструментов и поиск.
- Интересные и скрытые тикеры.
- Режим только интересные.
- Экспорт и импорт JSON без токена.

## Активация тикера

Текущая безопасная последовательность:

1. Найти видимую строку по data-row-id, data-symbol или data-ticker.
2. Если строки нет, открыть поиск через data-qa-icon=search-small.
3. Ввести точный тикер через native value setter и input/change.
4. Найти ссылку a.pro-menu-item с data-qa-tag=menu-item.
5. Если поиск не сработал, применить точный text-node fallback.

Search-flow был проверен в старой сессии на MAGN, SHU6, GAZP и SBERP. Это подтверждение реализации на тот момент, а не гарантия текущего DOM терминала.

## Подтверждённые проблемы

### P0: неполный прогрев окна

findClosest принимает первую доступную цену, даже если после запуска прошло существенно меньше windowSec.

Изолированный тест показал, что для окна 60 секунд сигнал может появиться уже через 3 секунды.

Нужное исправление:

- не рассчитывать delta, пока возраст истории выбранного FIGI меньше windowSec с допустимым отклонением около одного polling-интервала;
- добавить детерминированные тесты на прогрев.

### P0: окно 600 секунд и шестиминутный buffer TTL

PRICE_BUFFER_TTL_MS равен шести минутам, но popup предлагает 600 секунд.

Изолированный тест с ростом цены 100 → 110 за 10 минут показал 5.77% вместо 10%, потому что использовалась точка около четвёртой минуты.

Нужное исправление:

- хранить историю минимум windowSec плюс запас;
- либо временно убрать 600 секунд из UI;
- проверить диапазон priceLow/priceHigh.

### Выполнено: миграция контракта T-Invest

30 августа 2026 года host_permissions и BASE переведены на invest-public-api.tbank.ru, а GetCandles и GetLastPrices — на поле instrumentId. Ответ по-прежнему связывается со сканером по FIGI.

### P1: системное доверие сертификатам НУЦ Минцифры

API отдаёт TLS-цепочку Russian Trusted Root CA. Chrome без установленного корневого сертификата завершает запрос с ERR_CERT_AUTHORITY_INVALID до проверки токена.

Расширение не может обойти проверку TLS. Для Windows требуется установка корневого и выпускающего сертификатов с https://www.gosuslugi.ru/crt либо отдельный совместимый браузер со встроенной поддержкой этой цепочки.

NETWORK_OR_CERTIFICATE намеренно объединяет недоверенный сертификат и другие сетевые сбои, потому что fetch в service worker не предоставляет надёжный Chromium net error вызывающему JavaScript.

### P1: две установки в Chrome

В исходном профиле Chrome исторически были зарегистрированы две unpacked-копии с разными локальными ID. Эти ID зависят от установки и намеренно не публикуются. Перед живым тестом пользователь должен оставить включённой одну копию.

### P1: алерты не восстанавливаются

Background читает alerts из chrome.storage.session для popup, но content.js начинает с пустого массива и не загружает сохранённые строки после reload.

### P1: отсутствуют автоматические тесты

Нет package.json, тестового runner и фиксированного набора unit-тестов scanner.js.

Минимальный набор:

- полный прогрев окна;
- недостаточная история;
- несколько FIGI одного тикера;
- неактивная площадка;
- переключение активной площадки;
- ticker-level cooldown;
- TTL истории;
- окно 60/120/300/600;
- отсутствие цены или невалидная цена.

### P2: DOM-зависимая активация

Селекторы относятся к внутренней разметке терминала и требуют Windows smoke-теста после обновлений Т-Банка.

### P2: WebAudio

Chrome может приостановить AudioContext до первого пользовательского действия. Проверить тест-алерт на Windows.

## Почему React/Redux bridge не входит в активную версию

Экспериментальная ветка:

- читала React fiber;
- monkey-patch-ила Redux dispatch;
- перебирала сигнатуры обработчиков;
- могла записать объект вместо строки ticker;
- добавляла глобальный перехват window.fetch для исправления повреждённого workspace.

Один из экспериментов привёл к сохранению объекта symbol/figi в серверном workspace и падению терминала с React error 31.

Этот механизм не переносится в стабильную версию без отдельного решения, безопасного дизайна и тестирования вне живого аккаунта.
